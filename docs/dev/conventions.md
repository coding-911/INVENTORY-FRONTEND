# 프론트엔드 개발 컨벤션

> 원본(노션): https://app.notion.com/p/425b82ca31e581988e87f5eaa8d7064c  
> 내보낸 날짜: 2026-11-27. **노션이 원본이다.** 이 파일과 노션이 다르면 노션을 따른다.

> 🧩 프론트엔드(React + TypeScript + Vite) 코드를 쓸 때 지키는 규칙이다 (2026-11-27). 화면별 기능·API·권한은 [화면 목록](../screens/screen-list.md), 권한 표기는 [권한 매트릭스](../rules/permissions.md) 1.8절, API 공통 규칙은 [API 명세서](../api/api-spec.md) 1절, 백엔드 규칙은 백엔드 저장소의 `docs/dev/conventions.md`(노션 개발 컨벤션)를 본다.

> 쓰는 기술과 버전은 [프론트엔드 기술 스택](tech-stack.md)(2026-11-27 확정, ADR-18)을 본다.

## 1. 서버 데이터와 캐시

- 서버 데이터는 TanStack Query로만 다룬다. 받은 데이터를 화면 상태(useState 등)에 복사해 따로 들고 있지 않는다.
- 같은 API는 여러 화면이 같은 캐시를 같이 쓴다. 화면을 옮길 때마다 다시 부르지 않는다. 고르기용 목록(제품·품목군·창고·위치·거래처·프로젝트·통화)과, 화면 목록에서 여러 화면이 쓰는 API(거래 문서 목록, 배정 목록, 납품 현황, 재고 목록 등)가 대상이다.
- **업무 처리 뒤 다시 불러올 목록**: API 행의 "하고 나면 바뀌는 것"을 그대로 "처리가 끝나면 무효화할 캐시 목록"으로 쓴다. API별 무효화 목록은 **한 파일에 모은다**. 예: 발주 입고가 끝나면 재고 목록, 거래 문서 하나(잔량), 홈 집계를 새로 부른다. "입고했는데 재고 화면 숫자가 그대로"인 버그를 막기 위해서다.
- API 행의 "하고 나면 바뀌는 것"과 무효화 목록이 다르면 API 행을 기준으로 고친다.

## 2. 화면 주소

- 목록의 검색 조건(상태·기간·품목군·id·코드·검색어·페이지·정렬)과 상세 화면의 id는 주소(쿼리 문자열·경로)에 넣는다 (2026-11-27 확정).
  - 홈의 숫자를 눌러 그 조건의 목록으로 가는 것(UI-02)이 링크 하나로 된다.
  - 새로고침·뒤로 가기를 해도 조건이 유지된다.
  - 주소를 동료에게 보내면 같은 화면이 열린다. 권한은 서버가 검사하므로 주소를 알아도 데이터가 열리지는 않는다.
- **토큰·비밀번호·비밀번호 초기화 키·개인정보(전화번호 등)는 주소에 넣지 않는다.** 주소는 방문 기록과 서버 로그에 남는다.
- Nginx는 `Referrer-Policy: same-origin`을 보낸다(백엔드 기술 스택). 화면 주소가 외부 사이트로 넘어가지 않게 하기 위해서다.

## 3. API 타입

- 요청·응답 타입과 호출 함수는 백엔드 저장소에 커밋된 openapi.json에서 openapi-typescript·openapi-fetch로 만든다(기술 스택 3절). 손으로 타입을 쓰지 않는다.
- 금액 필드는 "없을 수도 있음"(optional) 타입이다. 금액 권한이 없으면 필드 자체가 오지 않기 때문이다(INV-83). 그래서 권한이 없을 때를 처리하지 않은 코드는 컴파일 단계에서 걸린다. 백엔드는 금액 필드를 OpenAPI에서 필수로 표시하지 않는다(개발 컨벤션 3절).
- API가 바뀌면 타입을 다시 만들고, 깨지는 곳을 같은 PR에서 고친다.

## 4. 권한

- 로그인 직후와 화면을 새로 열 때 `GET /api/v1/user/me`로 권한 목록(`permissions`, 권한 코드 13개 중 가진 것)을 받는다. 권한 판단은 이 값으로 한 곳에서만 한다. 역할 이름·코드로 판단하지 않는다. 역할은 `USER_MANAGE` 권한자가 바꿀 수 있는 묶음이기 때문이다(권한 매트릭스 1.8 구현).
- 권한 매트릭스의 권한 코드(`STOCK_OPERATE`, `COST_EDIT` 등 13개)를 코드 상수로 그대로 쓴다. "그리고"는 배열로 넘긴다. 예: `<Can need="APPROVE">`, `useCan(["DOCUMENT_MANAGE", "COST_EDIT"])`. 화면 목록 표의 권한 칸과 코드가 1:1로 맞아 검토하기 쉽다. "모두"는 검사하지 않는다(로그인만 하면 된다).
- 화면에서 숨기는 것은 편의다. 권한은 서버가 요청마다 검사한다.

## 6. 오류 메시지

- 백엔드 `ErrorCode` 목록을 그대로 내보내 화면 문구와 짝지은 표 하나를 둔다. 화면마다 문구를 따로 쓰지 않는다.
- 원본은 노션 허브의 에러 코드 정의서에 둔다.

> ⚠️ **확정 전**: 에러 코드 정의서는 아직 빈 페이지다. 백엔드 ErrorCode를 만들 때 함께 채운다.

## 7. 개발 방식

- **화면 ID를 코드에도 쓴다**: 라우트 이름, 테스트 이름, PR 제목에 `S-41`처럼 화면 ID를 넣는다. 이 화면이 어느 API·가이드 기준인지 거꾸로 찾을 수 있다.
- **화면 묶음 단위로 백엔드와 프론트를 같이 끝낸다**: 프론트 개발을 시작한 뒤에는 "S-20–S-27 + 해당 API"처럼 화면 묶음마다 백엔드와 프론트를 함께 마친다. 문서와 다른 점을 일찍 찾기 위해서다. 그 전까지는 백엔드부터 만든다.
- **백엔드 없이 화면 먼저 만들기**: OpenAPI로 가짜 서버(MSW)를 만들어 백엔드 API가 끝나기 전에도 화면을 만들고 시연한다.
- **검수 시나리오를 화면 자동 테스트로**: 노션 검수 시나리오 AT-01–21을 Playwright 테스트로 옮겨 검수 전에 화면 흐름을 자동으로 확인한다.
- Git·PR 규칙은 백엔드와 같다(개발 컨벤션 10절). 두 저장소에 걸친 변경은 PR을 따로 만들고 서로 링크하며, API를 바꾸는 백엔드 PR이 먼저 합쳐진다.
